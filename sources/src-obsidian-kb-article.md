# Source — Obsidian knowledge-base article (S. Magdy, Medium, Nov 2025)

**Raw file:** not archived (third-party article; clip it via Obsidian Web Clipper into `raw/` if a permanent copy is wanted). · **Ingested:** 2026-07-13

## What it is
A practitioner's guide to building a personal Obsidian knowledge base, based on ~3 years of use. Methodology source — it shaped this vault's conventions, not its domain content.

## Adopted into CLAUDE.md
- **Atomicity rule:** one concept per page; never let a page accumulate into a catch-all. Now a page convention, paired with the existing promote-at-3-citations rule and a new split trigger.
- **Inbox convention:** a `07-inbox/` folder as temporary parking for unclassified material, with a lint rule to empty it (the article's "Miscellaneous" folder, tightened).
- **Continuous refinement:** pages are living documents; a topic shaped by several sources is desirable, and repeated editing converges to quality. Reinforces the ingest workflow's update-don't-append behaviour.

## Considered and not adopted (with reasons)
- **Vault per field of study** — this venture is one ecosystem with heavily interlinked legal/technical/market knowledge; splitting vaults would sever exactly the cross-links that create value.
- **Python script + task scheduler for moving attachments** — unnecessary; Obsidian's "attachment folder path" setting (already `raw/assets/`, see README) solves it natively.
- **Hub/index folder, graph-view hygiene** — already present via `Home.md`, `index.md`, and the no-orphans rule from the LLM-wiki pattern.
